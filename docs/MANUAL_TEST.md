# 人による受け入れテスト

前提：Pixel_9a_Largeへ開発版APKをインストール済み。実在SNSの操作や結果判断はテスト担当者が行う。サンプルは外部サイトを開かない。

## 1. 初回と運用元

1. 起動画面でSNSを選ぶ。運用元未登録なら開始できないことを確認する。
2. 任意の表示名を登録し、開始ボタンを押す。確認ダイアログが表示され、「確認しました」で開始できることを確認する。
3. 同名運用元を追加し、内部IDで区別できることを確認する。作業中には運用元を切り替えない。切替はアプリを終了して再起動する。
4. 起動画面または設定の運用元管理で、選択中でない運用元をアーカイブ・復元する。

## 2. サンプル

1. 「サンプルデータを読み込む」を押し、サンプル運用元を選んで開始する。
2. 作業開始 → サンプルで結果入力を体験 → 手動で結果を選ぶ。
3. ブラウザやSNSが開かず、結果保存後も次の対象へ自動で進まないことを確認する。
4. 一覧・状態修正・メモ・グループ・操作履歴を確認する。

## 3. CSVと通常作業

1. 別の通常運用元で起動し、CSVインポートへ進む。
2. UTF-8／Shift_JISファイルを選択する。貼り付け入力も試す。
3. 正常・重複・不正行のプレビューを確認し、正常な新規行だけを取り込む。
4. 対象を開く。SNS未導入ならブラウザへ渡されることを確認する。端末のリンク設定によりブラウザが優先される場合もある。
5. アプリへ戻る。結果が自動登録されず、結果選択が表示されることを確認する。
6. 全8種の処理結果を試し、履歴を確認する。状態表記は利用者の判断を意味する。
7. 結果未登録で戻る場合のキャンセル確認と、スキップの履歴を確認する。
8. 結果未登録のままOSからアプリを終了し、再起動・運用元確認後に結果入力が復元されることを確認する。
9. 起動失敗時は起動回数と担当が増えず、再試行できることを確認する。

## 4. 担当と安全制限

1. 同じSNSに運用元A・Bを用意し、未割り当ての対象をAで開く。
2. 再起動してBを選ぶとAの対象が一覧に出ないことを確認する。
3. Aの対象詳細からBへ再割り当てし、Bで未処理・起動回数保持・Aの履歴保持となることを確認する。
4. スキップ対象は自動選出されない。一覧の状態修正から未処理へ戻すと選出される。
5. サンプルまたは検証用データで新規フォローを5件登録し、休憩案内が1回だけ出ることを確認する。
6. 15件／1時間または60件／24時間に達すると外部起動を停止し、結果入力・一覧・履歴・出力は利用できる。
7. 「以前からフォロー済み」「フォロー申請済み」は件数に入らず、「フォロー申請済み」から新規フォローへの変更で加算されることを確認する。

## 5. 出力・復元・削除

1. 対象CSVをOSのファイル保存画面で保存する。全SNS・全運用元・未割り当て・スキップを含むことを確認する。
2. CSVを再取り込みし、重複行で元の状態・担当・メモが変わらないことを確認する。
3. 完全バックアップZIPを保存する。accounts.csv、targets.csv、action_logs.csv、settings.csv、manifest.jsonを含む。
4. 復元確認画面で件数と重複を確認する。同SNS＋同表示名の候補が複数なら対応先を指定する。
5. 既存データ優先で追加され、現在のみ存在するデータが消えないことを確認する。
6. 復元した運用元・中断作業を利用するにはアプリを再起動する。
7. 設定の削除確認で表示される運用元を確認する。履歴のみ削除で制限カウントが変わらず、対象削除で未割り当て・他運用元の対象が消えないことを確認する。

## プラットフォーム確認

Androidの自動検証はAPI 37エミュレーターで実施。iOSの同手順はmacOS/Xcodeでビルド後、別途実施する。実在SNSでのログイン切替・Universal Links/App Linksの動作は端末とSNSアプリの設定にも依存する。
