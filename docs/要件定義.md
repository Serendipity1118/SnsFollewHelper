# フォロー作業支援アプリ 要件定義

- 文書名: 要件定義.md
- 対象: Flutter スマートフォンアプリ
- 対象OS: Android / iOS
- データ保存: 端末ローカルのみ
- 想定SNS: X / Instagram
- 目的: フォロー対象アカウントを順番に確認し、人が公式SNSアプリ上でフォロー操作を行う作業を支援する
- 重要方針: SNS操作の自動化を行わない

---

## 1. 背景・目的

事前に準備済みのX / Instagramアカウント一覧をスマートフォンへ取り込み、対象アカウントを1件ずつ公式SNSアプリで開く。

実際のフォロー操作は必ず利用者本人がX / Instagram公式アプリ上で行う。

Flutterアプリへ戻った後、利用者が対象アカウントの結果を手動で選択し、処理履歴をローカルDBへ保存する。

また、短時間・大量の連続操作を抑止するため、アプリ側に固定的な安全マージン制御を実装する。

本アプリは「自動フォローツール」ではなく「手動フォロー作業の対象管理・進捗管理・過剰操作抑止ツール」として設計する。

---

## 2. 基本原則

本アプリは以下を厳守する。

1. フォローボタンを自動操作しない。
2. X / Instagramアプリの画面内容を解析しない。
3. Accessibility API等を使用して他アプリのUIを読み取らない。
4. フォロー済み・未フォロー等の状態をSNS側から自動取得しない。
5. フォロワー・フォロー一覧等をスクレイピングしない。
6. 外部SNS APIを使ってフォロー操作を行わない。
7. Flutterへ戻ったことを契機に次のプロフィールを自動で開かない。
8. 次のプロフィールを開く操作は必ず利用者の明示的なタップで行う。
9. 短時間に大量のプロフィールを開かないよう、アプリ側で固定的なレート制御を行う。
10. 「この件数以下なら凍結されない」といった保証は行わない。
11. レート制御値はサービス側の公式安全値ではなく、本アプリ独自の負荷抑止用安全マージンとして扱う。
12. 検知回避を目的とするランダム遅延・人間らしい挙動の模倣等は実装しない。

## 3. 対象範囲

### 3.1 対象機能

- CSVファイルから対象アカウントを取り込む
- ローカルDBへ対象アカウントを保存する
- X / Instagram別に対象を管理する
- 未処理対象を1件ずつ表示する
- 公式SNSアプリまたは対応URLでプロフィールを開く
- Flutter復帰後に結果入力画面を表示する
- 利用者による手動結果入力
- 処理履歴保存
- 重複対象の抑止
- 処理済み対象の除外
- 検索・絞り込み
- 進捗表示
- 安全マージン制御
- ローカルデータのバックアップ用CSVエクスポート
- 全データ削除

### 3.2 対象外

- フォローの自動実行
- フォロー解除の自動実行
- 自動いいね
- 自動DM
- 自動コメント
- SNS画面のOCR
- SNS画面のAccessibility解析
- SNS APIによるフォロー状態取得
- フォロワー一覧の自動収集
- スクレイピング
- 外部サーバー
- Firebase / Firestore
- ログインサーバー
- ユーザー間データ共有
- バックグラウンドでのSNS操作
- SNSアプリから戻った時点での自動次画面遷移

## 5. 対象SNS

### 5.1 X

プロフィールURL形式:

```text
https://x.com/{username}
```

### 5.2 Instagram

プロフィールURL形式:

```text
https://www.instagram.com/{username}/
```

### 5.3 URL起動方針

- `url_launcher` を使用する
- `LaunchMode.externalApplication` を基本とする
- HTTPS URLを優先する
- 非公開・非公式な独自URL Schemeへ依存しない
- 外部アプリ起動失敗時はエラーを表示する
- アプリ起動失敗時に勝手に別対象へ遷移しない

## 6. ユーザーフロー

### 6.1 初回

```text
アプリ起動
  ↓
CSVインポート
  ↓
内容確認
  ↓
ローカルDB保存
  ↓
ダッシュボード
```

### 6.2 通常作業

```text
未処理対象を表示
  ↓
利用者が「プロフィールを開く」をタップ
  ↓
安全マージンチェック
  ↓
許可
  ↓
X / Instagram公式アプリを開く
  ↓
人がプロフィールを確認
  ↓
人が必要に応じてフォロー
  ↓
Flutterへ戻る
  ↓
結果選択画面
  ↓
利用者が結果をタップ
  ↓
ローカルDBへ保存
  ↓
利用者が「次のアカウントを開く」をタップ
  ↓
次対象
```

### 6.3 重要

Flutterへ戻っただけでは以下を行わない。

- フォロー済み判定
- 次対象への自動遷移
- 次プロフィールの自動起動
- 結果の自動登録

## 7. アカウント状態

`TargetStatus` は以下とする。

| 値 | 表示 | 意味 |
|---|---|---|
| pending | 未処理 | 未確認 |
| followed | フォロー済み | 利用者が手動でフォロー済みと登録 |
| notFollowed | 未フォロー | 確認したがフォローしなかった |
| privateAccount | 非公開 | 非公開アカウント |
| suspended | 凍結・停止 | 利用者が凍結・停止と判断 |
| notFound | 存在しない | URL無効・アカウントなし等 |
| skipped | スキップ | 今回処理しない |

SNS側の状態をアプリが自動判定してはならない。

## 8. CSVインポート

### 8.1 必須カラム

```csv
platform,username
instagram,example_user_1
x,example_user_2
```

### 8.2 任意カラム

```text
profile_url
memo
group
```

### 8.3 platform許容値

以下を大文字小文字を無視して許可する。

```text
x
twitter
instagram
ig
```

DB保存時は以下へ正規化する。

```text
x
instagram
```

### 8.4 username正規化

- 前後空白除去
- 先頭`@`除去
- 空文字禁止
- URL形式が入力されている場合は可能であればusernameを抽出
- 不正値はインポート確認画面でエラー表示

### 8.5 重複

同一SNS + 同一usernameを一意キーとして扱う。

```text
(platform, normalized_username)
```

既存対象と重複する場合:

- デフォルト: 新規追加しない
- インポート結果に「重複」と表示
- 既存の処理状態を上書きしない

SQLite + Driftを採用する。

### 9.1 targets

| カラム | 型 | 必須 | 説明 |
|---|---|---:|---|
| id | TEXT | yes | UUID |
| platform | TEXT | yes | x / instagram |
| username | TEXT | yes | 正規化済み |
| profileUrl | TEXT | yes | 起動用URL |
| status | TEXT | yes | TargetStatus |
| memo | TEXT | no | メモ |
| groupName | TEXT | no | 任意グループ |
| importedAt | DATETIME | yes | 取込日時 |
| processedAt | DATETIME | no | 結果登録日時 |
| followedAt | DATETIME | no | followed登録日時 |
| lastOpenedAt | DATETIME | no | 最終プロフィール起動日時 |
| openCount | INTEGER | yes | 起動回数 |
| createdAt | DATETIME | yes | 作成日時 |
| updatedAt | DATETIME | yes | 更新日時 |

Unique:

```text
(platform, username)
```

### 9.2 action_logs

すべてローカル保存。

| カラム | 型 | 説明 |
|---|---|---|
| id | TEXT | UUID |
| targetId | TEXT | targets.id |
| platform | TEXT | x / instagram |
| actionType | TEXT | profileOpened / statusChanged |
| statusBefore | TEXT | 任意 |
| statusAfter | TEXT | 任意 |
| occurredAt | DATETIME | 発生日時 |

### 9.3 app_settings

安全マージン等の設定を保存する。

## 10. 安全マージン制御

### 10.1 目的

SNS側の技術的な上限を使い切ることを目的とせず、本アプリ独自の保守的な制御により短時間・大量の連続操作を抑止する。

本制御は凍結・制限を防止する保証ではない。

### 10.2 初期値

初期実装ではX / Instagram共通で以下をデフォルトとする。

| 項目 | 初期値 |
|---|---:|
| 直近24時間のfollowed上限 | 20件 |
| 直近1時間のfollowed上限 | 5件 |
| 1セッションのfollowed上限 | 10件 |
| プロフィール起動の最小間隔 | 60秒 |
| 連続5件followed後の休憩 | 10分 |

これらは「公式安全値」ではない。

### 10.3 ローリング方式

日付単位のリセットは禁止する。

例:

```text
23:50に10件
00:10に10件
```

のような短時間集中を避けるため、常に現在時刻から過去24時間で集計する。

```text
now - 24 hours ～ now
```

### 10.4 判定対象

安全制御は、利用者が`followed`として登録した履歴を基準とする。

プロフィール起動そのものについても最小間隔を設ける。

### 10.5 制限到達時

「プロフィールを開く」および「次のアカウントを開く」を無効化する。

結果入力、履歴確認、CSVエクスポートは可能とする。

表示例:

```text
現在、安全マージンによる操作制限中です。

この制限はSNS側の公式上限ではなく、
短時間の連続操作を抑止するためのアプリ独自制御です。

再開可能: 14:35
```

### 10.6 禁止事項

以下は実装しない。

- ランダムな待機時間
- 検知回避のためのタイミング調整
- 人間の操作パターン模倣
- 制限を自動で回避する処理

### 11.1 ダッシュボード

表示:

- X 未処理件数
- Instagram 未処理件数
- 本日ではなく「直近24時間」のfollowed件数
- 直近1時間のfollowed件数
- 現在のセッションfollowed件数
- 安全制御状態
- 作業開始
- 対象一覧
- CSVインポート
- エクスポート
- 設定

### 11.2 作業画面

表示:

- platform
- username
- profile URL
- memo
- group
- 現在状態

```text

[未フォロー]
[非公開]
[凍結・停止]
[存在しない]
```

```text
[次のアカウントを開く]

```

### 11.3 一覧画面

- platform
- username
- status
- processedAt
- 検索
- platformフィルタ
- statusフィルタ
- groupフィルタ

### 11.4 詳細画面

- 全データ表示
- memo編集
- 状態の手動変更
- 操作履歴表示

### 11.5 インポート画面

1. CSV選択
2. パース
3. 正常 / エラー / 重複件数表示

### 11.6 設定画面

MVPでは安全制御値は表示のみとし、利用者が容易に上限を引き上げられない構成を推奨する。

開発用ビルドではコード定数または開発者設定から変更可能としてよい。

## 12. セッション定義

アプリ起動時に新しい作業セッションを開始する。

以下でセッション終了:

- 利用者が「作業終了」
- アプリプロセス終了
- 30分以上操作なし

セッションカウントは安全制御の追加条件であり、24時間・1時間ローリング制限とは独立する。

---

## 13. アプリライフサイクル

`AppLifecycleState`を利用する。

SNS起動前:

```text
externalLaunchPending = true
targetId = 現在対象
```

Flutterが`resumed`になった場合:

```text
externalLaunchPending == true
```

であれば結果入力UIを表示可能にする。

ただし`resumed`だけで以下は行わない。

- status更新
- followed登録
- 次対象起動
- 次対象選択

---

## 14. 対象選択ロジック

デフォルト:

```text
status == pending
ORDER BY importedAt ASC, id ASC
```

現在対象の処理後、次に未処理の対象を候補として表示する。

X / Instagramを混在させるか、platformごとに作業するかは作業開始時に選択可能とする。

## 17. 非機能要件

### 17.1 セキュリティ

- SNSパスワードを保存しない
- SNS Cookieを保存しない
- SNSアクセストークンを保存しない
- 外部サーバーへ対象データを送信しない
- Crashログ等へusernameを不用意に出力しない

### 17.2 オフライン

CSV取込・一覧・履歴管理は完全オフラインで動作する。

SNSプロフィール起動後の通信はX / Instagram公式アプリ側に依存する。

### 17.3 パフォーマンス

10万件程度の対象をローカルDBで管理できる設計とする。

一覧はページングまたは遅延ロードする。

### 17.4 可用性

SNSアプリ起動失敗時でもアプリがクラッシュしない。

### 17.5 保守性

- 時刻取得を抽象化する
- URL起動を抽象化する
- DBアクセスをRepository経由にする
- 安全マージン判定を独立サービスにする

## 20. App Store / Google Play 審査対応要件

### 20.1 基本方針
本アプリは第三者SNS上の操作を自動化しない。ストア掲載文・審査説明も実際の機能と一致させる。

- 利用者が事前に用意した対象アカウント一覧を端末内で管理する
- 利用者が対象プロフィールを明示的に開く
- SNS上のフォロー等の操作は利用者本人が行う
- Flutterへ戻った後、利用者が結果を手動登録する
- 第三者SNSの画面・状態・フォロー状態を取得しない
- 審査目的の機能隠蔽・誤認を招く説明は行わない

### 20.2 商標・ブランド
- X / Instagram / Metaの公式ロゴをアプリアイコンに使用しない
- 公式・公認・提携と誤認させる名称や表現を使用しない
- 第三者SNS名は対象プラットフォーム識別のため必要最小限に使用する
- アプリ内に非提携表記を置く

### 20.3 「このアプリについて」画面
以下の趣旨を表示する。

```text
本アプリはSNS上の操作を自動化するものではありません。
プロフィールの確認、フォロー等の操作、および処理結果の判断はすべて利用者自身が行います。
本アプリはX、Instagram、Meta等とは提携・承認・後援関係にありません。
```

### 20.4 ブラウザフォールバック
X / Instagram公式アプリが未インストールでも、HTTPSプロフィールURLをSafari / Chrome等で開けるようにする。独自URL Schemeのみへ依存しない。

### 20.5 審査用サンプルデータ
「サンプルデータを読み込む」を提供する。実在人物・実在アカウントは使用しない。

例:
```text
demo_account_001
demo_account_002
demo_account_003
```

サンプルデータでは実在SNSプロフィールを開かない。

### 20.6 プライバシーポリシー
最低限以下を明記する。

- 対象アカウント情報と作業履歴は原則端末内のみ保存
- 開発者独自サーバーへ送信しない
- SNSパスワード、Cookie、アクセストークンを取得・保存しない
- 第三者SNSのフォロー状態を取得しない
- 分析SDK・広告SDKを導入する場合は別途開示する

MVPでは広告SDK・分析SDKを導入しないことを推奨する。

### 20.7 App Store Review Notes
以下の趣旨を記載する。

```text
This app does not automate any action on third-party social networking services.
It only manages a user-provided list of profile URLs locally on the device.
The user manually opens each profile, performs any action directly in the third-party app or browser, returns to this app, and manually records the result.
The app does not access, scrape, inspect, or control third-party applications.
No social-network credentials, cookies, or access tokens are collected or stored.
```

### 20.8 Google Play掲載説明
以下を明確にする。

- 手動作業支援アプリである
- 第三者アプリを自動操作しない
- Accessibility APIを使用しない
- 外部SNS認証情報を取得しない
- 対象情報・履歴は端末内で管理する

### 20.9 ストア掲載画像
推奨:
- ダッシュボード
- 対象一覧
- 作業画面
- 手動結果入力
- 履歴
- 安全マージン表示

避ける:
- フォロワー増加を強調する表現
- 「爆増」「自動」「大量フォロー」「BAN回避」等
- 第三者SNS UIが主役の画像

### 20.10 最低限の機能性
単なるURLランチャーと見なされないよう、以下をMVP必須とする。

- CSVインポート
- ローカルDB管理
- 状態分類
- 検索・絞り込み
- 作業履歴
- 安全マージン管理
- CSVエクスポート
- サンプルデータ
